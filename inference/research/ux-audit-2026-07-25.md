# UX and README Audit - 2026-07-25

## Executive Summary

The three-course platform has a solid shared shell for theme, sidebar, search, and responsive layout, but the UX is not yet a coherent multi-course system. Linux behaves like a book that opens directly into chapter 1, while Distributed Systems and Inference behave like standalone courses with home maps, quizzes, and completion rings. The largest user-facing gaps are README drift, absent Inference documentation, inconsistent progress semantics, and brittle localStorage writes that can prevent Distributed/Inference chapters from rendering. Cross-course discovery exists only as low-prominence sidebar links, so first-time users may not understand this is an 86-chapter, three-course platform.

## Critical Issues (must fix - user-facing bugs or major confusion points)

### Inference Course Is Missing From README
- Severity: Critical
- Where: `README.md:1`, `README.md:5`, `README.md:11`, `README.md:24`, `README.md:34`, `README.md:101`, `README.md:113`, `README.md:144`
- What happens: A GitHub visitor sees "The Linux Deep Dive" plus a later Distributed Systems section, but no equivalent Inference Engineering section. Docker instructions mention `/distributed/` but not `/inference/`.
- Why it matters: The repo now serves three courses, but the primary landing page still frames it as one Linux guide with one extra course.
- Fix direction: Reframe the README as a multi-course technical education platform, with all three courses listed near the top and equal run/deployment links.

### Inference Chapter Count Is Internally Inconsistent
- Severity: High
- Where: `inference/assets/inf.js:9`, `inference/assets/inf.js:15`, `inference/assets/inf.js:29`, `inference/assets/inf.js:44`, `inference/assets/inf.js:58`, `inference/assets/inf.js:70`, `inference/assets/inf.js:86`
- What happens: The audit brief describes Inference as 16 chapters, but the repo contains 17 Markdown files under `inference/content/`, and `inf.js` registers 17 chapters.
- Why it matters: Users and contributors will not know whether one chapter is extra, missing from docs, or accidental.
- Fix direction: Decide the canonical count, then update README/site copy and course registry to match.

### localStorage Write Failures Can Break Distributed and Inference Chapter Rendering
- Severity: High
- Where: `distributed/assets/ds.js:90`, `distributed/assets/ds.js:101`, `distributed/assets/ds.js:381`, `distributed/assets/ds.js:383`, `inference/assets/inf.js:106`, `inference/assets/inf.js:117`, `inference/assets/inf.js:398`, `inference/assets/inf.js:400`
- What happens: `renderChapter()` calls `setLastVisited()` before fetching/rendering. If localStorage quota is exceeded or storage is blocked, `saveProgress()` can throw, and the chapter may never render.
- Why it matters: A persistence feature should degrade gracefully; it should not block reading.
- Fix direction: Wrap all progress writes in `try/catch` and treat persistence failures as non-fatal.

### Linux Has No Course Home While the Other Two Courses Do
- Severity: High
- Where: `assets/app.js:144`, `assets/app.js:505`, `assets/app.js:507`, `assets/app.js:610`, `distributed/assets/ds.js:215`, `distributed/assets/ds.js:473`, `inference/assets/inf.js:231`, `inference/assets/inf.js:490`
- What happens: Visiting `/` opens `start-here` immediately. Visiting `/distributed/` or `/inference/` opens a course landing page with modules, progress, and start/continue CTA.
- Why it matters: First-time users get a platform/course-map experience in two sub-sites but not the largest course.
- Fix direction: Standardize on either course homes for all three or direct-to-first-chapter for all three. For a multi-course platform, a Linux home/course map is the better standard.

### Direct File Opening Fails Despite Static-Site Expectations
- Severity: High
- Where: `assets/app.js:546`, `assets/app.js:581`, `distributed/assets/ds.js:390`, `distributed/assets/ds.js:396`, `inference/assets/inf.js:407`, `inference/assets/inf.js:413`, `README.md:48`
- What happens: Content is loaded via `fetch()`, so `file://` opening commonly fails. The app shows an error that tells users to run a server.
- Why it matters: The platform is described as static and easy to open, but the actual UX depends on HTTP serving.
- Fix direction: Document "static files served over HTTP" consistently, or add a file-safe fallback/build artifact.

## Consistency Issues (things that differ between sub-sites but should not)

### Progress Semantics Differ by Course
- Where: `assets/app.js:231`, `assets/app.js:350`, `assets/app.js:355`, `assets/app.js:357`, `distributed/assets/ds.js:84`, `distributed/assets/ds.js:215`, `distributed/assets/ds.js:357`, `inference/assets/inf.js:100`, `inference/assets/inf.js:231`, `inference/assets/inf.js:374`
- What differs: Linux marks chapters read manually or automatically at end of page. Distributed/Inference mark completion through quizzes or a manual completion button. Linux shows sidebar count; the others show a home ring but no sidebar summary.
- Recommendation: Standardize terminology and UI: "read" vs "complete" should mean the same thing across all courses, and every course should expose a comparable sidebar progress summary.

### Sidebar Active-Item Scroll Behavior Differs
- Where: `assets/app.js:510`, `assets/app.js:515`, `assets/app.js:516`, `distributed/assets/ds.js:207`, `inference/assets/inf.js:223`
- What differs: Linux scrolls the active TOC item into view. Distributed and Inference only toggle `.active`.
- Recommendation: Standardize on Linux behavior so deep links and keyboard navigation keep the current chapter visible in the sidebar.

### Reading Scroll Restoration Exists Only in Linux
- Where: `assets/app.js:273`, `assets/app.js:318`, `assets/app.js:573`, `assets/app.js:574`, `distributed/assets/ds.js:452`, `inference/assets/inf.js:469`
- What differs: Linux stores/restores scroll in `sessionStorage`. Distributed and Inference always scroll to top on chapter render.
- Recommendation: Either add scroll memory to all courses or remove it from the shared UX promise.

### Mobile Auto-Hiding Contents Bar Only Works in Linux
- Where: `assets/app.js:331`, `assets/app.js:352`, `assets/app.js:360`, `distributed/assets/ds.js:161`, `inference/assets/inf.js:177`, `assets/style.css:926`, `assets/style.css:927`
- What differs: CSS supports `#sidebar-toggle.hide`, but only Linux JS calls `updateToggleBar()`.
- Recommendation: Move toggle auto-hide logic into shared code or remove the behavior.

### On-Page TOC and Heading Deep Links Exist Only in Linux
- Where: `index.html:69`, `assets/app.js:403`, `assets/app.js:457`, `assets/style.css:782`, `distributed/index.html:64`, `inference/index.html:64`
- What differs: Linux has heading anchors and a right-side "On this page" rail. Distributed/Inference have neither.
- Recommendation: Standardize chapter-reading affordances across all courses, especially for long technical chapters.

### Error Handling for Unknown Hashes Differs
- Where: `assets/app.js:499`, `assets/app.js:507`, `distributed/assets/ds.js:458`, `distributed/assets/ds.js:462`, `inference/assets/inf.js:475`, `inference/assets/inf.js:479`
- What differs: Linux silently falls back to `start-here`; Distributed/Inference silently fall back to the course home.
- Recommendation: Show a consistent "chapter not found" state with links back to course home and search.

### Search Failure State Is Misleading
- Where: `assets/app.js:624`, `assets/app.js:637`, `assets/app.js:639`, `assets/app.js:679`, `distributed/assets/ds.js:487`, `distributed/assets/ds.js:500`, `distributed/assets/ds.js:547`, `inference/assets/inf.js:504`, `inference/assets/inf.js:517`, `inference/assets/inf.js:564`
- What differs: Scope is correctly per-course, but if chapter fetches fail, failed docs are dropped and the UI still says "Type to search all N chapters."
- Recommendation: Add an index failure/partial-index state, including "0/N chapters indexed" when fetch fails.

### Cross-Course Navigation Is Present But Low-Prominence
- Where: `index.html:43`, `index.html:48`, `distributed/index.html:47`, `distributed/index.html:53`, `inference/index.html:47`, `inference/index.html:53`
- What differs: Cross-course links live low in the sidebar. On mobile, they are hidden inside the drawer until the user opens it.
- Recommendation: Add a consistent course switcher near the course title or a platform home link visible on first visit.

### Cross-Course Labels Are Inconsistent
- Where: `index.html:44`, `index.html:49`, `distributed/index.html:48`, `distributed/index.html:54`, `inference/index.html:48`, `inference/index.html:54`
- What differs: Linux says "Standalone course"; Distributed/Inference say "Back to the main guide" and "Sister course."
- Recommendation: Standardize vocabulary around "Courses" or "Course switcher."

### Inference CSS Header Is a Copy/Paste Error
- Where: `inference/assets/inf.css:1`, `inference/assets/inf.css:2`, `distributed/assets/ds.css:1`, `distributed/assets/ds.css:2`
- What differs: `inf.css` identifies itself as "Distributed Systems course-only presentation."
- Recommendation: Rename the header to Inference Engineering to reduce maintainer confusion.

## README Issues

### README Frames the Repo as One Main Course Plus One Add-On
- Severity: Critical
- What is wrong: `README.md:1` starts with only "The Linux Deep Dive"; `README.md:3` and `README.md:5` describe only the Linux guide; `README.md:24` adds Distributed Systems as a feature; Inference is absent.
- Suggested restructure: Start with a platform-level heading, then a three-course table: Linux Deep Dive, Distributed Systems, Inference Engineering, each with chapter count, path, audience, and local URL.

### Docker Instructions Omit Inference
- Severity: High
- What is wrong: `README.md:34` lists only Linux and Distributed URLs.
- Suggested restructure: Include all three URLs: `/`, `/distributed/`, and `/inference/`.

### Repository Layout Omits Inference
- Severity: High
- What is wrong: `README.md:115` through `README.md:128` lists root and `distributed/`, but not `inference/` or `inference/research/`.
- Suggested restructure: Add `inference/index.html`, `inference/assets/`, `inference/content/`, and optionally `inference/research/`.

### Contributing Instructions Omit Inference
- Severity: High
- What is wrong: `README.md:135` through `README.md:144` explains Linux and Distributed contribution paths only.
- Suggested restructure: Add the Inference path: chapters in `inference/content/`, registry in `inference/assets/inf.js`, styles in `inference/assets/inf.css`.

### Feature List Is Not Platform-Accurate
- Severity: Medium
- What is wrong: `README.md:11` says "A 56-chapter curriculum"; `README.md:24` mentions only a separate 13-chapter Distributed Systems course; no mention of the 17 registered Inference chapters.
- Suggested restructure: Split "Platform features" from "Course catalog." State total registered chapters as 56 + 13 + 17 = 86, unless the intended Inference count is corrected to 16.

### Curriculum Overview Is Linux-Only Without Saying So Clearly Enough
- Severity: Medium
- What is wrong: `README.md:50` says "Curriculum overview" and `README.md:52` says "main curriculum," but a stranger may expect all three courses.
- Suggested restructure: Rename to "Linux Deep Dive curriculum," then add parallel summaries for Distributed and Inference.

## Minor Polish (low-severity improvements)

### Search Placeholder Does Not Signal Course Scope
`index.html:77`, `distributed/index.html:76`, and `inference/index.html:76` all say "Search all chapters…". Since search is scoped per sub-site, use course-aware placeholders or a visible scoped label.

### Search Keyboard Hint Shows `/` But Also Supports Ctrl/Cmd-K
The button displays `/` in all three shells (`index.html:36`, `distributed/index.html:38`, `inference/index.html:38`), while README advertises both `/` and `Ctrl/Cmd-K` (`README.md:14`). Consider showing both in the modal or tooltip.

### Linux Sidebar Footer Differs From Course Sidebars
Linux has a progress summary and Markdown-rendering note (`index.html:53` through `index.html:55`); Distributed/Inference only say progress is saved locally (`distributed/index.html:59`, `inference/index.html:59`). Standardize the footer role.

### Loading State Only Exists on Initial HTML
Initial shells show `Loading…` (`index.html:61`, `distributed/index.html:66`, `inference/index.html:66`), but route changes generally leave the previous content visible until fetch finishes (`assets/app.js:545`, `distributed/assets/ds.js:387`, `inference/assets/inf.js:404`). Consider route-level loading feedback.

### Distributed and Inference Do Not Wrap Tables
Linux wraps tables after render (`assets/app.js:422`, `assets/app.js:568`), while Distributed/Inference do not call equivalent logic. Wide Markdown tables exist in both course folders, e.g. `distributed/content/real-world-architectures.md:149` and `inference/content/quantization.md:170`.

## What Works Well (things that are already right - do not touch these)

- Theme pre-application before first paint is implemented in all three HTML shells (`index.html:8`, `distributed/index.html:8`, `inference/index.html:8`).
- Theme and desktop sidebar collapsed state intentionally persist across sub-sites via shared keys (`ldd-theme`, `ldd-nav-collapsed`) in all three readers.
- Search is correctly scoped to each course's registered chapter list: Linux `BOOK`, Distributed `COURSE`, Inference `COURSE`.
- Distributed and Inference have strong first-time course homes with module maps, progress rings, and clear start/continue CTAs (`distributed/assets/ds.js:215`, `inference/assets/inf.js:231`).
- Mobile drawer mechanics are shared and sound: sticky top toggle, slide-over sidebar, scrim close, and body scroll lock (`assets/style.css:897` through `assets/style.css:981`).
- Cross-course links exist from each sub-site to the other courses, even though their prominence and labels need standardization.
